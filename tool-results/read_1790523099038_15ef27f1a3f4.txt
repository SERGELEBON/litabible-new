    59→- Created 6 App Router route handlers under `src/app/api/`:
    60→  - `messe/[date]/route.ts`        — GET; validates date, calls fetchMesse, returns `{source:"aelf-api", data}` on success or `{source:"local-fallback", data:null}` on failure (HTTP 200 in both cases so the client falls back to local files transparently). Bad date → 400. Cache: s-maxage=600/stale-while-revalidate=3600 on success, no-store on fallback.
    61→  - `office/[hour]/[date]/route.ts`— GET; validates hour against allowed list (lectures/laudes/tierce/sext/none/vepres/complies) and date, then same fallback pattern as messe. Includes `hour` and `date` echo in the response envelope.
    62→  - `bible/chapter/route.ts`      — GET; query params `version`, `book`, `chapter`. Resolves version via `getBibleVersion` (defaults to LSG), resolves book id, calls `getChapter`. Returns full `ChapterResult` on success; 502 + error envelope when both upstreams fail; 400 on bad inputs.
    63→  - `bible/search/route.ts`       — GET; query params `q` (required, ≥2 chars), `version` (default LSG), `limit` (1..100, default 30). Returns `{results, translation, query}` on success or 400 on bad input.
    64→  - `bible/versions/route.ts`     — GET; static — returns `{versions, languages:{fr,en,es}}` so the frontend can populate a version selector. Long-cache (max-age=86400/s-maxage=604800).
    65→  - `contact/route.ts`            — POST; zod-validated `{name,email,subject,message,captchaToken?}`. On valid payload: logs to server console and returns `{success:true}` (no DB, no email backend wired up yet — single hook for future). On bad JSON / validation failure: 400 with `{success:false, error, issues?}`.
    66→- All routes use `NextRequest`/`NextResponse` from `next/server`, default Node runtime (no `export const runtime = "edge"`), and never crash — every code path returns a JSON response.
